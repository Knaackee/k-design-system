# Plan picker: Storybook review

Scope approved on 31 October 2026: Web library and Storybook only. Flutter,
Widgetbook, checkout integration and consuming applications are intentionally deferred.

## Research and limits

- [NN/g: Comparison tables](https://www.nngroup.com/articles/comparison-tables/):
  use aligned attributes for decisions across a small number of offers. Tables
  suit feature-heavy tiers; they add unnecessary weight to a single offer.
- [Apple: Subscriptions](https://developer.apple.com/app-store/subscriptions/):
  disclose the actual billed subscription amount clearly. An annual price's
  monthly equivalent is supplementary, not a replacement for the annual bill.
- [RevenueCat: Four paywall redesign case studies](https://www.revenuecat.com/blog/growth/paywall-redesigns-case-studies):
  results vary with audience, pricing, copy and placement. These are case studies,
  not controlled evidence that one layout universally converts best.
- Mobbin visual references:
  [Moonly](https://mobbin.com/screens/b2a7f4f6-e03e-4875-97ec-79c299a244c7)
  for compact rows; [Liven](https://mobbin.com/screens/a612cffd-939d-471f-9b89-bf734058ab1a)
  for stacked choices; [Campsite](https://mobbin.com/screens/fc7ecce6-3653-4cda-927e-37b124f227ea)
  for side-by-side offers; [Klarna](https://mobbin.com/screens/c74ef0f0-135e-496a-8c6d-3d3fd57e2f1d)
  for a compact selector with focused details. Visual inspiration does not establish conversion performance.

## Two components, five layouts

`KPlanCard` owns the offer content and accessible selection surface.
`KPlanPicker` owns composition and emits controlled selection events.

| layout     | Use                                                                                  |
| ---------- | ------------------------------------------------------------------------------------ |
| cards      | Two or three tiers, visible side by side on wide screens                             |
| stacked    | Full offer cards beneath one another, all details available                          |
| compact    | Short selection rows plus selected-plan benefits                                     |
| focused    | A plan selector and one detail card, also available on desktop                       |
| comparison | Offer cards and a semantic attribute table with horizontal overflow on small screens |

Options include mobile focused/stacked behavior, optional interval selection,
intro slot, sticky action, optional badges/emphasis, unavailable/loading states,
and consumer-supplied color overrides. All copy, price formatting and comparison
values belong to the consumer. Selection never initiates payment.

Annual/monthly intervals describe billing of a tier. The Duration Offers story
separately demonstrates monthly, annual and one-time offers with a single interval
key per offer. A single offer has no unnecessary plan selector; a single interval
has no interval switch. No default recommendation, popularity, testimonial,
discount or countdown is generated by the library.

## Review and experiments

Stories cover the layouts, one/two/three plans, interval choices, duration offers,
benefit-led introduction, no preselection, unavailable prices, loading, dark theme,
larger text, mobile comparison and a sticky action. Prices are fictitious fixtures.

Before consumer integration, visually accept the preferred combinations and
implement matching Flutter fixtures. Evaluate conversion together with price
comprehension, accidental purchase reports, refunds and early cancellations.
Compare layouts with identical prices/content and predefined cohorts; do not
claim uplift from screenshots or vendor case studies.

Validation commands: `pnpm --filter @k-design-system/ui build`,
`pnpm --filter @k-design-system/storybook typecheck`, and
`node --test packages/web/ui/plan-picker.test.mjs`.
Full repository verification is separate and has an existing unrelated formatting
failure in `docs/sound-parity-review.md`; no release readiness is claimed.
